# RFC 0029 — 0.3.0 expansion: planning, decentralized multi-agent, and a wider benchmark

- **Status:** accepted
- **Author:** FABLINE
- **Date:** 2026-11-24
- **Related:** ADR 0041, `benchmarks/factory-v0.2/spec.md`, P3 review
- **Approved by:** owner

## Summary

0.3.0 is a **focused expansion**, not a grab bag. It adds two flagship gaps
(planning/world models and decentralized multi-agent), two cheap gap closers
(uncertainty calibration and causal intervention), an optional generative
pilot, a frozen `factory-v0.2` benchmark, and a practical wizard/viewer layer.

The frozen `factory-v0.1` benchmark remains immutable.

## Why this scope

The coverage map is strong in tabular, self-supervised, small control, and
power/risk tasks. The largest absences are:

- planning / world models;
- true per-agent multi-agent learning;
- generative layouts/recipes;
- deep RL / offline RL beyond tabular Q and BC;
- causal interventions;
- uncertainty beyond power;
- public efficiency comparisons.

Closing all of them in one minor release would be low quality. The release
therefore prioritizes **two new decision surfaces**, closes two gaps with
task-level work, and treats generative modeling as a stretch.

## Scope

### Flagship 1 — planning / world models

A planning task on the existing factory world:

- a small finite-horizon decision with a budget;
- a known or learned model can be used for rollout;
- compare random shooting, CEM/MPC, scripted, and a model-free baseline;
- metrics: plan success, budget use, rollout error, latency.

Candidate: repair/build planning on the 32×16 twin-line or 48×24 spread layout.
No new world.

### Flagship 2 — decentralized multi-agent

A per-agent task on the 48×24 distributed layout:

- each crew has a local view and a communication budget;
- compare centralized scripted, decentralized scripted, shared reports, private
  views, and a learned per-agent policy;
- metrics: score, success, report use, local/global gap.

This upgrades P2 from centralized/scripted coordination to actual decentralized
decision-making.

### Cheap gap closers

- **Uncertainty:** calibration (Brier, NLL, ECE, reliability) on fault onset and
  maintenance predictions, not only power.
- **Causal:** an intervention task (disable/remove a component) comparing
  observational and interventional predictions.

### Stretch

- **Generative layout/recipe pilot:** validity/diversity task, not a full
  generative world. It does not block 0.3.0.

### Benchmark

- Freeze `factory-v0.2` after the pilots, not before.
- Candidate scope: 10–12 tasks, ~180 episodes, stronger test/shift/layout
  splits, and a wider baseline matrix.
- `factory-v0.1` is unchanged and remains the stable reference.

### GUI

- `fabline wizard`: terminal/TUI flow for config/task/seeds/output and running
  smoke/suite commands. No new dependency.
- Viewer QoL: replay browser, task-card viewer, result summary, and “open last
  run” from the wizard.
- Pygame remains optional; the core stays headless.

## Phases and gates

| Phase | Work | Gate |
|---|---|---|
| 0 | RFC/ADR + `factory-v0.2` spec | approved scope |
| 1 | Planning task pilot | task card, prereg, 5 seeds, plan success/latency |
| 2 | Decentralized multi-agent pilot | task card, prereg, local/global and communication gates |
| 3 | Calibration + causal tasks | task cards, calibration/intervention gates |
| 4 | Generative pilot (optional) | validity/diversity gate; may slip |
| 5 | Benchmark candidate | 10–12 stable tasks, expected summary, CI |
| 6 | Wizard + viewer QoL | headless tests, SDL dummy, no new deps |
| 7 | `v0.3.0` release audit | frozen `factory-v0.2`, clean export, assets |

A phase that misses its gate is reported negative and does **not** enter the
frozen benchmark.

## Quality gates

- Every new task has a card and a pre-registration.
- Every mechanic has an ADR and tests.
- Every benchmark task has a baseline, split, metric, and expected summary.
- `factory-v0.1` hash and assets remain unchanged.
- No new dependency without an ADR; the wizard uses stdlib.
- Benchmark freeze requires at least 20 test and 20 shift/layout episodes.
- The GUI is not part of the benchmark and must not mutate state.

## Non-goals

- closing every coverage gap in one release;
- a new world or a new frozen benchmark before the pilots are stable;
- deep RL or offline RL from scratch;
- PyPI or Zenodo publication;
- generative modeling if it threatens the release date.

## Risks

- **Planning task may be a scripted puzzle.** Mitigate with a model-quality
  metric and a kill criterion.
- **Decentralized multi-agent may be shallow.** Require a local/global gap and
  a learned policy that beats private scripted.
- **Benchmark scope creep.** Freeze only tasks that pass their pilots.
- **GUI scope creep.** Wizard first; visual polish last.
- **Compute cost.** Keep 5-seed pilots bounded and report runtime.

## Decision

Accepted. The next artifacts are the `factory-v0.2` spec, then the planning
pilot. No mechanic code starts before the spec is committed.
