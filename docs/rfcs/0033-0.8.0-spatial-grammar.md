# RFC 0033 — 0.8.0 spatial grammar and stochastic faults

- **Status:** proposed; owner approved both surfaces; `factory-v0.7` not frozen
  (0099 H2 fail); spatial diagnostic; `factory-v0.8` pending
- **Author:** FABLINE
- **Date:** 2026-11-28
- **Related:** [roadmap 0.5.0–0.8.0](../roadmap-0.5.0-0.8.0.md),
  [coverage map](../coverage-map.md), RFC 0032, ADR 0043,
  [`factory-v0.6`](../../benchmarks/factory-v0.6/card.md)
- **Predecessor:** 0.7.0 sequential-crew challenge; 0.7.1 communication
  negative (0096)

## Summary

0.8.0 has **two independent benchmark surfaces**:

1. **Spatial production grammar** (`factory-v0.7`): larger/randomized layouts,
   obstacles, splitters/mergers, routing, and scale transfer.
2. **Stochastic faults/POMDP** (`factory-v0.8`): hidden wear, noisy sensors,
   inspection, repair/continue, and root-cause prediction.

The two are not mixed in one task or one expected summary. The spatial grammar
is the first implementation slice; the fault/POMDP tier follows. Either tier
can ship without the other if its validity gates fail. The default world hash
and frozen v0.1–v0.6 assets must remain unchanged.

## Why

The current factory is small and fixed. That limits spatial, relational, OOD,
routing, and belief-state questions:

- grid/CNN and flattened entity views are tested on one small layout family;
- splitters/mergers and route choice are absent;
- scale transfer is untested;
- stochastic faults, hidden wear, sensor noise, and inspect/repair/continue are
  not a frozen task;
- the 0.7.0 sequential-crew challenge is valid but the learned baselines fail;
- the 0.7.1 communication experiment is negative.

The owner requested both surfaces for 0.8.0. They must remain separable so a
weak result in one does not hide behind the other.

## Spatial production grammar — `factory-v0.7`

Opt-in `SpatialGrammarConfig`:

- width/height and obstacle density;
- one to three production lines;
- random line offsets and orientations;
- splitters/mergers on belts;
- shared ore/power/crew resources across lines;
- optional dead ends/loops;
- deterministic seeded generation and replay.

Tasks:

| Task | Kind | What it tests | Baselines |
|---|---|---|---|
| layout-shift | regression | throughput/bottleneck on unseen layouts | GBDT, MLP, CNN, MPNN, Transformer |
| scale-transfer | regression | train small, test large | same; domain generalization |
| route-control | control | choose splitter/merger routes | A*/MCTS, GNN, tabular Q, OR |
| line-balancing | control | balance multiple lines | OR/CP-SAT, RL, GNN |

First slice: generator + **layout-shift**; route control is second. Layout
seeds are split by layout, not episode; no layout-seed leakage.

## Stochastic faults/POMDP — `factory-v0.8`

Opt-in `StochasticFaultConfig`:

- stochastic onset hazard depends on wear, load, and maintenance;
- sensor noise/drift and false positives/negatives;
- hidden wear/fault state;
- correlated failures via shared power/load;
- inspect/repair/continue actions;
- true latent state in `info` for labels and evaluation only.

Tasks:

| Task | Kind | What it tests | Baselines |
|---|---|---|---|
| fault-detection-noise | detection/calibration | onset under noisy sensors | GBDT, HMM, Kalman/particle, survival, conformal |
| pomdp-maintenance | control | inspect/repair/continue with hidden wear | threshold/reactive, belief RL, POMDP solver |
| root-cause | prediction/causal | source of a production drop | causal discovery, GBDT, graph models |

Gates: detection skill over base rate; ECE ≤0.05 only with skill; control gain
over the best threshold; deterministic seeds/hashes; calibration reported only
with detection skill. Do not add another redundant sensor view.

### First-slice pilot (0097)

The layout-shift pilot trained on 16×8, 20×12, and 24×16 base layouts and tested
on 32×24 spread, 24×20 random, and 24×20 obstacle layouts. Linear R² is 0.98 on
the raw base score but collapses on the large (−1.29) and obstacle (−303)
shifts; a per-line normalized target generalizes on the random shift (0.60) but
still fails the large (−0.99) and obstacle (−18.8) shifts. A padded-grid CNN
follow-up (0098) was positive, and the formal fresh-seed block (0099) confirms:
CNN base 0.970; large/random/obstacle shifts 0.534/0.976/0.806; H1–H5 pass.
`factory-v0.7` is frozen. MPNN/Transformer are a baseline expansion, not part of
the freeze.

## Splits and gates

- Spatial: layout-seed splits (train/val/test/shift), item conservation,
  splitter/merger invariants, OOD gap, model ordering.
- Faults: fault-seed splits, fault-free hash unchanged when disabled, hidden
  state seeded and replayable, detection skill, calibration, control gain.
- Each tier has its own expected summary and freeze review.
- Freeze `factory-v0.7` after the spatial generator + layout-shift pass; freeze
  `factory-v0.8` after the fault/POMDP tier passes. Do not mix tiers.

## Phases

1. **Spatial generator + layout-shift** (first slice): opt-in grammar,
   invariant tests, layout split, throughput/bottleneck baselines.
2. **Route control / scale transfer** (spatial second slice).
3. **Stochastic fault config + noise views**: deterministic hazard/noise,
   fault-detection-noise and pomdp-maintenance task cards.
4. **POMDP control + root-cause**: belief-state baselines and calibration.
5. **Independent freezes**: `factory-v0.7` and `factory-v0.8` separately.
6. **Optional closers**: line balancing, inventory/quality only if they add a
   new decision.

Generative layout/recipe remains conditional on a grammar audit (≥20 unique
structures, diversity ≥0.25, validity ≥0.90) and moves to 0.9.0+ unless it passes.

## Scope cuts

- No new item types or recipes.
- No inventory/depletion, quality/defect, or trains/logistics in the first slice.
- No learned layout generator; the grammar is procedural.
- No mixing faults into spatial tasks or spatial structure into fault tasks.
- No changes to frozen v0.1–v0.6 assets or default hashes.
- No generative model on the current small grammar.

## Risks and kill criteria

- **Two mechanics in one release.** Keep them independent; if one fails its
  validity gate, ship the other. Do not combine them into a half-finished task.
- **Spatial content explosion.** Keep one to three lines and a small entity set.
- **No separation.** If layout shift does not separate model families, keep it
  as a diagnostic and do not freeze `factory-v0.7`.
- **Fault redundancy.** If sensor views are redundant or calibration has no
  skill, retire that view; do not add another calibration sweep.
- **Split leakage.** Layout and fault splits must be disjoint and reproducible.
- **Scope creep.** Inventory/quality/generative work needs a new decision.

## Alternatives

- **Spatial only.** The roadmap's original 0.8.0; the owner requested the fault
  tier too, so this is no longer the scope.
- **Faults only.** Leaves the spatial/OOD gap open; not chosen.
- **Mix both in one task.** Rejected: it would confound layout and belief state
  and make a negative result uninterpretable.
- **Generative layout first.** Conditional on the grammar audit; move to 0.9.0+.

## Decision

Proposed. The owner approved including both surfaces. The first-slice design
(spatial generator + layout-shift) and the fault-tier task cards/pre-regs still
need approval before implementation.
