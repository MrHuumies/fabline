# RFC 0033 — 0.8.0 spatial production grammar

- **Status:** proposed
- **Author:** FABLINE
- **Date:** 2026-11-28
- **Related:** [roadmap 0.5.0–0.8.0](../roadmap-0.5.0-0.8.0.md),
  [coverage map](../coverage-map.md), RFC 0032, ADR 0043,
  [`factory-v0.6`](../../benchmarks/factory-v0.6/card.md)
- **Predecessor:** 0.7.0 sequential-crew challenge; 0.7.1 communication
  negative (0096)

## Summary

0.8.0 makes **layout and flow structure a first-class variable**: larger and
randomized layouts, obstacles, splitters/mergers, routing, and scale transfer.
It is one flagship mechanic — the **spatial production grammar** — and it does
not add new item types, inventory, or generative models.

The default world hash and frozen v0.1–v0.6 assets must remain unchanged. The
new grammar is opt-in and task-layer where possible.

## Why

The current factory is deliberately small and fixed. That makes the core
benchmark reproducible, but it limits the spatial, relational, OOD, and
routing questions:

- throughput-grid and the grid CNN are evaluated on one small layout family;
- flattened entity views collapse on held-out combinations;
- splitters/mergers and route choice are absent;
- scale transfer is untested;
- the 0.7.0 sequential-crew challenge has a fixed 32×32 layout.

The 0.7.0/0.7.1 line is closed: the sequential task is a challenge and the
local-report communication experiment is negative. The next coverage gain is
spatial structure, not another communication or fault variant.

## Mechanic

### Layout grammar

Opt-in `SpatialGrammarConfig`:

- width/height and obstacle density;
- one to three production lines;
- random line offsets and orientations;
- splitters/mergers on belts;
- shared ore/power/crew resources across lines;
- optional dead ends/loops;
- deterministic seeded generation and replay.

The grammar is a generator, not a learned model. Item conservation and
splitter/merger invariants are enforced by construction and tests.

### Tasks

| Task | Kind | What it tests | Baselines |
|---|---|---|---|
| layout-shift | regression | throughput/bottleneck on unseen layouts | GBDT, MLP, CNN, MPNN, Transformer |
| scale-transfer | regression | train small, test large | same; domain generalization |
| route-control | control | choose splitter/merger routes | A*/MCTS, GNN, tabular Q, OR |
| line-balancing | control | balance multiple lines | OR/CP-SAT, RL, GNN |

The first slice is **layout-shift** plus the generator. Route control is the
second slice and requires a new action contract. Line balancing and inventory
are optional closers only if they reuse the same surface.

## Splits and gates

- Layout seeds are split by layout, not by episode; no layout-seed leakage.
- Report in-distribution vs OOD gap and model ordering.
- Task gates: learned skill over mean/persistence; OOD gap and ordering stable
  across seeds; deterministic generation; item conservation.
- Control gates: scripted/oracle reference, learned gap, success, cost.
- Freeze `factory-v0.7` only after the first two slices pass; a working
  generator without a separating task is a diagnostic, not a benchmark.

## Phases

1. **Generator + layout-shift.** Opt-in grammar, generator tests, layout split,
   throughput/bottleneck baselines. This is the first pre-registration.
2. **Route control.** Splitter/merger action contract, A*/MCTS and Q baselines.
3. **Scale transfer.** Train small, test large; report OOD gap and ordering.
4. **Optional closers.** Line balancing, inventory, quality; only if they add a
   new decision over the existing production tasks.
5. **Freeze `factory-v0.7`** with a spatial tier after the slices pass.

Generative layout/recipe remains conditional on a grammar audit (at least 20
unique structures, diversity ≥0.25, validity ≥0.90). Do not train a generative
model on the current small grammar.

## Scope cuts

- No new item types or recipes.
- No inventory/depletion, quality/defect, or trains/logistics in the first
  slice.
- No learned layout generator; the grammar is procedural.
- No changes to frozen v0.1–v0.6 assets or default hashes.
- No stochastic faults/POMDP in 0.8.0; that line is deferred.

## Risks and kill criteria

- **Generator complexity.** If the grammar produces invalid or non-conserving
  layouts, stop and fix invariants before any model run.
- **No separation.** If layout shift does not separate model families, keep it
  as a diagnostic and do not freeze.
- **Content explosion.** Keep one to three lines and a small entity set.
- **Split leakage.** Layout splits must be disjoint and reproducible.
- **Scope creep.** Inventory/quality/generative work needs a new decision.

## Alternatives

- **Stochastic faults/POMDP.** Deferred from 0.7.0; it is a second mechanic and
  the calibration/fault lines are already broad. Revisit as a 0.9.0 or a
  conditional closer, not in the 0.8.0 flagship.
- **Inventory/depletion or quality first.** Reuses the surface but adds a
  resource/quality axis before the spatial grammar is tested; defer.
- **Generative layout first.** Conditional on the grammar audit; do not start
  with a model.
- **Another sequential-crew/communication variant.** Retired; no.

## Decision

Proposed. The owner must approve the 0.8.0 flagship and the first slice before
implementation. The next artifact is an ADR plus layout-shift task cards and a
pre-registration.
