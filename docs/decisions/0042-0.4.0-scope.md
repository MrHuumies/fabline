# ADR 0042 — 0.4.0 scope and demand-driven production

- **Status:** accepted
- **Date:** 2026-11-26
- **Related:** RFC 0030, RFC 0029, ADR 0041,
  [`factory-v0.2`](../../benchmarks/factory-v0.2/card.md),
  [0.3.0 coverage review](../coverage-review-0.3.0.md)
- **Approved by:** owner

## Context

0.3.0 closed the planning, calibration, causal, decentralized, generative, and
efficiency lines at their current scope. The remaining gaps are structural:

- production has one fixed gear recipe and no product-mix decision;
- no demand-side uncertainty or deadline pressure;
- deep/offline RL has no non-toy control task;
- the current line grammar has only seven unique sequences, so a generative
  pilot is not meaningful;
- transition models have a representation ceiling.

The owner approved RFC 0030: demand-driven multi-item production as one
integrated 0.4.0 mechanic.

## Decision

1. 0.4.0 adds an **opt-in multi-item production tree** and a **seeded order
   stream** as one demand-driven production mechanic.
2. The first implementation slice is a **production-mix line**: the assembler
   can make `GEAR` (current) or `COMPONENT`; component is a second deliverable.
   The full `INGOT + COMPONENT -> GEAR` assembly edge is Phase 1b, gated on the
   Phase 1 pilot showing a non-trivial product-mix decision.
3. The order stream is a task layer with quantities, deadlines, and values; it
   does not change the default world.
4. Add a deep/offline RL baseline track (PPO/SAC optional Torch, BC) on the new
   order-control task.
5. A `factory-v0.3` benchmark is a candidate, frozen only after the pilots pass.
   `factory-v0.2` remains immutable.
6. No new dependency is required; Torch stays optional.
7. The default `factory-v0.1`/`factory-v0.2` hashes must remain unchanged when
   the new config is absent.

## First slice — production mix

- `Item.COMPONENT` is added without changing default delivered keys.
- `ProductionConfig` is opt-in and selects the assembler recipe:
  `GEAR` from ingots or `COMPONENT` from ingots.
- A production task wrapper chooses the recipe at decision boundaries; the
  frozen grid action contract is unchanged.
- Component deliveries score through an opt-in config value; default scoring is
  unchanged.
- A production observation/task view is added without changing the frozen
  vector/grid/entity adapters.

## Alternatives considered

- **Energy storage first.** Smaller, but the power line is already broad and
  risks another scripted scheduling puzzle.
- **Quality/rework first.** Good uncertainty axis, but narrower than product
  mix and overlaps the mixed calibration line.
- **Richer layout grammar only.** Fixes generative diversity but adds little
  planning/RL coverage.
- **Deep/offline RL only.** Adds baselines but no new decision surface.
- **No new mechanic.** Not enough research coverage for 0.4.0.

## Consequences

- The world gains one opt-in production mechanic with a strict default-hash
  invariant.
- Tasks can share the same episodes across planning, control, calibration, and
  causal views.
- The 0.4.0 release may ship without a new frozen benchmark if the pilots do not
  stabilize.
- Generative work waits for a recipe/line grammar with enough structural
  diversity.
