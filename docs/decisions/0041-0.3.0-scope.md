# ADR 0041 — 0.3.0 expansion and `factory-v0.2`

- **Status:** accepted
- **Date:** 2026-11-24
- **Related:** RFC 0029, `benchmarks/factory-v0.2/spec.md`, P3 review

## Context

Coverage is broad in tabular/self-supervised/small-control tasks but absent in
planning/world models, decentralized multi-agent, generative tasks, deep/offline
RL, and causal interventions. `factory-v0.1` is intentionally narrow (46
episodes, 6 test episodes). The owner approved a 0.3.0 expansion.

## Decision

1. 0.3.0 focuses on two flagship gaps: planning/world models and decentralized
   multi-agent.
2. Add two cheap gap closers: fault/maintenance calibration and a causal
   intervention task.
3. Treat generative layout/recipe work as a stretch pilot, not release-blocking.
4. Draft `factory-v0.2` now; freeze it only after the pilots pass.
5. Keep `factory-v0.1` immutable; the new benchmark gets a new version.
6. Add a stdlib-only `fabline wizard` and viewer QoL after commands/results
   settle.
7. Release `v0.3.0` only after a clean benchmark freeze and release audit.

## Alternatives considered

- **Close every gap in 0.3.0.** Rejected: quality and scope risk.
- **Freeze `factory-v0.2` first.** Rejected: it would freeze untested tasks.
- **Build the GUI first.** Rejected: commands and result formats will change.
- **New world.** Rejected: the current world can answer the planning,
  multi-agent, calibration, and causal questions with opt-in tasks.

## Consequences

- The release has a clear theme: decision surfaces plus a wider benchmark.
- Some gaps (generative, deep RL) may remain open after 0.3.0.
- The benchmark candidate is reviewed before freeze; failing tasks are
  reported negative and excluded.
- The public package keeps the headless core and optional Pygame.
